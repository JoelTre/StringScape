# Batch processing

Serve the modeller and this folder together over HTTPS or localhost, and open `batch/` in Chrome or Edge. Connecting an output folder uses the File System Access API. The app remembers the most recently connected folder in the browser and reconnects automatically when permission is still available. If the browser requires permission again, select Reconnect previous folder. Choose a CSV with these exact headers:

- `What do you want a model of?`
- `Reference PDB IDs`
- `AlphaFold IDs, UniProt IDs, or PDB IDs`

Blank fields are passed as empty inputs. The modeller's normal search and target discovery run where needed. Choose a species and, where required, upload its STRING sequences and aliases before starting. The modeller’s species selector can also fetch files for supported model organisms. The selection and available files apply to every row. Use the AI card and the collapsed Settings card before starting; the settings are the modeller's live build controls. The batch runs sequentially in the displayed modeller. Pause waits for the current row and can be resumed; Stop waits for the current row. The estimated completion time uses the average duration of rows attempted in the current run and excludes time spent paused. Reconnecting a folder resumes by skipping completed rows with identical values in the three input columns; failed rows are retried. Use a different folder to rerun a completed row or change its settings. Rows have a 30-minute timeout. External services and an active browser tab may be needed for builds.

Each completed row is stored under `models/<input hash>/` with a portable modeller session (`session.json`, a single indexed `session-buffers-<id>.bin` file and any input attachments), the final `model.cif`, a full-sized PNG and small transparent PNG thumbnail when image capture succeeds, and `result.json`. `batch-manifest.json` indexes completed rows and keeps model-level means; per-residue confidence values are stored in each model’s `result.json`. On connecting an older results folder, the app copies any legacy per-residue values to the corresponding result file before removing them from the manifest. The session excludes AI credentials. A simulated model image uses the modeller's auto-fitted overview capture after the build; without simulation it uses the prepared overview. The results viewer restores the saved session in the original modeller. Keep all files in each model folder together. Older sessions with separate `buffer-*.bin` files remain supported.

Confidence charts show one mean per model and all available per-residue values separately. The model confidence mean follows the modeller's overall score (excluding locked residues); other per-model means average available residue values. Constraint confidence is the mean of each residue's available restraint confidence values, with locked residues scored as 1. Missing scores are excluded. A restored session can recompute derived values from its saved model data.

During a run, the status above Run progress shows the current modeller or file-saving step. Performance diagnostics reports average elapsed time per step for successful and failed rows separately. The app saves the timings in `batch-diagnostics.json` in the connected folder; existing runs without diagnostics are not included. Saving the diagnostics file itself is not included in the step timings.

Newly saved sessions use the modeller’s compact session format. They keep the saved model view’s residue-level PAE and confidence values, but omit pairwise PAE matrices. Restoring a compact session preserves those colours; reload pairwise PAE in the modeller’s Validation report before starting or resuming simulation or inspecting pair-level PAE. Older full sessions remain readable.

The Settings card offers three save modes. Full session retains the modeller working session; Most data, but fast (the default) saves a viewer snapshot without working drafts, spring networks or input attachments. Both omit full PAE matrices. Minimal, fastest saves model.cif, bonds.bin, residue confidence values and atom-to-bond keys in result.json, a thumbnail, membrane geometry and basic metadata; it does not save a session or full-size image. The minimal viewer reconstructs the model from mmCIF, and colour modes that need omitted data are unavailable. A minimal gallery image opens the thumbnail. Full sessions and older viewer snapshots remain readable.

For new images with detected membrane geometry, each filename includes the projected vertical position of the membrane centre, for example `image-membrane-y-450px.png` and `thumbnail-membrane-y-90px.png`. The value counts pixels from the top edge of that specific image and is rounded to the nearest pixel; thumbnail coordinates use its 180-pixel height. If two membranes are present, the names use `membrane1` and `membrane2`. This is the projection of each membrane centre, not the top or bottom edge of the membrane, and it can fall outside the image if the centre projects outside the crop. Existing results keep their original filenames.

The Model gallery can switch to Cell landscape. Membrane thumbnails with recorded positions are aligned at the same vertical height with no horizontal gap; other thumbnails are arranged below. Hover to see a model name or click to open its saved image. Older images without recorded membrane positions appear below because their alignment cannot be recovered reliably. The landscape uses a capped canvas backing resolution to limit memory for large collections.

New model images and thumbnails have transparent backgrounds. For older opaque JPEG or PNG images, the gallery approximates transparency by removing light or dark background connected to the image edge; original files remain unchanged. Some background enclosed entirely by model details may remain visible.
