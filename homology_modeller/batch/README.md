# Batch processing

Serve the modeller and this folder together over HTTPS or localhost, and open `batch/` in Chrome or Edge. Connecting an output folder uses the File System Access API. Choose a CSV with these exact headers:

- `What do you want a model of?`
- `Reference PDB IDs`
- `AlphaFold IDs, UniProt IDs, or PDB IDs`

Blank fields are passed as empty inputs. The modeller's normal search and target discovery run where needed. Choose a species and, where required, upload its STRING sequences and aliases before starting. The modeller’s species selector can also fetch files for supported model organisms. The selection and available files apply to every row. Use the AI card and the collapsed Settings card before starting; the settings are the modeller's live build controls. The batch runs sequentially in the displayed modeller. Pause waits for the current row and can be resumed; Stop waits for the current row. The estimated completion time uses the average duration of rows attempted in the current run and excludes time spent paused. Reconnecting a folder resumes by skipping completed rows with identical values in the three input columns; failed rows are retried. Use a different folder to rerun a completed row or change its settings. Rows have a 30-minute timeout. External services and an active browser tab may be needed for builds.

Each completed row is stored under `models/<input hash>/` with a portable modeller session (`session.json`, a single indexed `session-buffers-<id>.bin` file and any input attachments), the final `model.cif`, a full-sized PNG and small JPEG thumbnail when image capture succeeds, and `result.json`. `batch-manifest.json` indexes completed rows and keeps model-level means; per-residue confidence values are stored in each model’s `result.json`. On connecting an older results folder, the app copies any legacy per-residue values to the corresponding result file before removing them from the manifest. The session excludes AI credentials. A simulated model image uses the modeller's auto-fitted overview capture after the build; without simulation it uses the prepared overview. The results viewer restores the saved session in the original modeller. Keep all files in each model folder together. Older sessions with separate `buffer-*.bin` files remain supported.

Confidence charts show one mean per model and all available per-residue values separately. The model confidence mean follows the modeller's overall score (excluding locked residues); other per-model means average available residue values. Constraint confidence is the mean of each residue's available restraint confidence values, with locked residues scored as 1. Missing scores are excluded. A restored session can recompute derived values from its saved model data.

During a run, the status above Run progress shows the current modeller or file-saving step. Performance diagnostics reports average elapsed time per step for successful and failed rows separately. The app saves the timings in `batch-diagnostics.json` in the connected folder; existing runs without diagnostics are not included. Saving the diagnostics file itself is not included in the step timings.

Newly saved sessions use the modeller’s compact session format. They keep the saved model view’s residue-level PAE and confidence values, but omit pairwise PAE matrices. Restoring a compact session preserves those colours; reload pairwise PAE in the modeller’s Validation report before starting or resuming simulation or inspecting pair-level PAE. Older full sessions remain readable.

The Settings card has a Save full session data switch, off by default. Off saves a viewer-only snapshot with model and per-residue data but omits working drafts, spring networks and input attachments; it cannot resume a simulation. On saves a complete modeller working session. Both use compact residue-level PAE instead of full PAE matrices. Live simulation and animation-dependent colours may be unavailable in a viewer snapshot when their underlying data was not present.
