# Protein modeller benchmark

Serve this directory alongside the modeller over HTTPS, as on GitHub Pages. Open `/homology_modeller/benchmark/` in Chrome or Edge. Upload a CSV with `PDB ID` and `Reference mappings` columns. Mappings have the form `A:P25732:group=A; B:P25732:group=B`. Connect an output folder and run the queue. The browser remembers the last folder and reconnects automatically when permission remains available; otherwise, use Reconnect last folder to grant access again. Connecting another folder replaces the displayed folder results. External RCSB, AlphaFold and UniProt services must be reachable.

Each PDB ID already completed, failed or skipped in the connected folder is skipped, regardless of the input CSV or settings. Entries taking over five minutes are marked skipped. Interrupted entries can be retried. To retry a failed or skipped PDB or run a completed PDB again, choose a different output folder. Each entry stores a reference, masked reference, settings, prediction, residue table, result, and overview image when available. The root manifest stores entry status and paths; detailed results remain in each entry folder. The results page loads and calculates views on demand. Select “Save combined files to folder” on that page to generate the root summary and residue CSVs and `benchmark-results.json`. Previously exported combined files are snapshots and are not updated automatically. A result JSON can also be opened directly in the results tab. Older manifests and results-only folders remain supported and are converted when needed; existing per-entry files and aggregate exports are retained, while the manifest is replaced by the compact index after migration.

The Diagnostics button shows average elapsed time for each recorded stage, separately for successful and failed builds (including time-limit skips). The build count per stage excludes builds that did not reach it. Timings are saved in `benchmark-diagnostics.json` in the connected folder; builds run before diagnostics was added do not have stage timings. Aggregate saving is included as a separate stage.

Biological assembly 1 is the default. If it is unavailable the entry fails instead of silently changing to deposited coordinates. The binding site detector is the modeller's existing detector. When no protein binding-site residues are found, a seeded random segment of up to ten observed residues per protein chain is used. The seed is a deterministic 32-bit FNV-1a hash of `1:<uppercase PDB ID>`; the seed, derivation and selected residues are saved. Non-protein residues are retained.

Distances are Cα distances in the reference coordinate frame, in ångströms. Full reference and target sequences are aligned, then matched by chain and identical residue. Ambiguous chain matches and residues without a matching model residue are left unavailable rather than guessed. Counts use reference residues with observed Cα coordinates; missing coordinates cannot be measured. RMSD is the square root of the mean squared distance of the matched residues. The prediction CIF is exported in the reference frame. Confidence scores range from 0 to 1; sequence coverage is a percentage. Disorder is unavailable when UniProt annotations are unavailable. The overview image is the modeller's pre-simulation snapshot, even when simulation is enabled. The result also records the maximum displacement among matched kept residues as a lock diagnostic.

The results page includes a residue confidence-versus-distance plot restricted to rows explicitly marked `Kept? = No`. Older residue tables without that column are excluded from this plot rather than inferred from alignment status. A separate plot compares the input CSV's `Missing residues (%)` with removed-residue RMSD; rows missing either value are excluded. Percentages are interpreted on a 0–100 scale, with or without a trailing percent sign.

The run completion estimate uses the mean duration of PDBs completed in the current run, adjusted for the current entry's elapsed time. It excludes IDs already completed, failed or skipped and is unavailable until one PDB completes or while the queue is paused. It is an estimate, since complex sizes and service response times vary.

Plot colour controls can show PDB IDs or a continuous scale based on per-PDB removed or missing residue counts or percentages. Grey means the selected value is unavailable. Missing-residue values come from the input CSV, not inferred coordinates. The first scatter plot can instead plot one point per PDB, using the mean confidence and distance over that PDB's comparable residue pairs; its trend is fitted to whichever points are displayed. Quadratic trends require at least three distinct x values. Residue tables are rendered only for the selected PDB. Overview images are read from the connected folder on selection, with a display-all option.

Each plot has its own non-disordered-residue filter. When enabled, only reference residue rows with `Non-disordered? = Yes` are used; missing or unknown annotations are excluded rather than assumed ordered. Model-level confidence is the mean of available confidence scores in those reference rows, and RMSDs are recalculated from available distances. Kept/removed counts and percentages are recalculated from classified eligible reference rows. Original missing-residue counts and percentages remain the values from the input CSV, since absent residues cannot be classified using the residue table. Filtered confidence may differ from the modeller's overall confidence, which can include residues not represented in the reference table.

New runs also save per-residue φ and ψ circular differences, their mean torsion-angle difference in degrees, and lDDT-Cα. Backbone angles require N, Cα and C coordinates and an intact peptide bond in both structures. lDDT-Cα considers distinct reference Cα pairs less than 15 Å apart, including inter-chain pairs, using strict error thresholds of 0.5, 1, 2 and 4 Å. Each residue's score averages its comparable neighbour checks; pairs without both predicted Cα atoms are excluded and counted as missing. The summary lDDT is weighted by comparable reference pairs, while the per-PDB scatter points are unweighted means of residues with both confidence and metric values. Reference pairs with no comparable prediction are recorded separately; residues without comparable neighbours have unavailable lDDT. These metrics are computed from reference Cα-containing residues, not absent coordinates. Existing results are not retroactively recalculated; use a new output folder for new runs because completed IDs are skipped.

The comparison viewer reads the original reference and predicted mmCIF from the selected folder and keeps them in the saved reference frame. New runs include AlphaFold pLDDT, the modeller's per-residue mean PAE to represented residues in the same AlphaFold chain, and prediction chain/residue mapping in the residue table. Missing values and older runs are displayed as unavailable. The viewer's backbone-issue and clash colours are Cα-based approximations, not the modeller's exact simulation diagnostics. The viewer offers Backbone, Ball & Stick, Ribbon, Curves and Space filling styles. Ribbon reuses the modeller's ribbon generator with secondary structures inferred from each saved structure; Curves uses a smoothed Cα tube. The modeller's Surface style is not implemented in this comparison viewer.

New runs also save `prediction-residues.csv` and prediction residue metadata in each `result.json`. This covers all predicted protein residues, including those without a reference match, and records the modeller's aligned/locked flags and confidence. The comparison viewer uses this mapping for prediction colours. For older runs, the viewer can recover missing prediction mappings from same-chain sequence alignment to reference rows, but values not present in those rows remain unavailable. Ambiguous prediction identifiers are left unavailable.

New benchmark runs save schema version 2 features in both residue CSVs and per-entry JSON. Per-entry JSON deduplicates repeated directional anchor-pair strings in an `anchorPairValues` dictionary (`anchorPairEncoding: dictionary-v1`); indices are expanded when reading results, and CSV exports retain full directional values. `prediction-residues.csv` includes prediction residues without a matching reference; aggregate residue results remain reference-based. Features are measured at the final benchmark comparison stage (post-simulation when enabled). The settings file records the feature schema, benchmark release identifier, simulation setting and modeller settings; this identifier is not a source-control commit hash. Archive the exact app source or commit separately for reproducibility.

Sequence distances are differences in AlphaFold sequence position within the same model block and AlphaFold chain, to residues actually used in alignment with a reference counterpart. Internal gap length is the number of sequence positions between anchors; terminal or unanchored lengths span the represented prediction sequence. Missing anchors have blank distances. Gap type, alignment evidence, secondary structure, the modeller's maximum normalized Cα clash overlap and mean absolute non-backbone restraint strain are recorded. Strain and clashes are final-coordinate features, not pre-simulation inputs. The PAE columns include both matrix directions to the nearest anchors on each side and means/counts across other aligned anchors. Directional pairs are saved as JSON in the CSV cell, keyed by AlphaFold anchor position; null means unavailable. PAE is only available within the same AlphaFold source chain. The main PAE column remains the mean symmetrised error to all represented same-chain residues.

Per-entry `gaps.csv` groups prediction residues between the same sequence anchors; its RMSD includes all matched rows in that group, and its counts identify removed rows. `chains.csv` reports prediction and reference counts per prediction block and removed-residue RMSD. Reference residues without a prediction cannot be assigned to these prediction-side groups. The new feature explorer compares numeric or coded categorical features with fixed-frame placement distance, lDDT-Cα, torsion difference, or per-PDB removed RMSD; it defaults to removed residues. For RMSD it uses one mean feature value per PDB. Categorical codes are labels, not a continuous scale. Correlations are descriptive; residues from the same protein are not independent. Older result bundles continue to load, with absent features excluded.

The feature and accuracy summary is calculated when its Calculate feature summary button is selected; changing the residue subset clears it until recalculated.

## Reference sequence metadata in masked input

When the original mmCIF supplies a complete, internally consistent polymer sequence and sequence positions for a protein chain, the generated `masked-reference.cif` includes that chain's polymer sequence and the sequence positions of the retained atoms. Removed coordinates are not included. This information is part of the saved input file itself: uploading that same masked file directly into the modeller provides the same information as a benchmark build. The full reference is used only after model building for the benchmark comparison. If the source lacks usable polymer metadata, no sequence is invented and the modeller uses its coordinate-sequence alignment fallback.

Benchmark results produced before this change used a different alignment input and should not be mixed with new results for confidence calibration without recording that distinction. Existing completed entries are skipped, so use a new output folder to rerun them.

## UniProt fallback benchmarking

Select **Allow natural UniProt fallback** to benchmark the ordinary modeller behaviour when AlphaFold returns no model. Select **Force UniProt sequence (paired benchmark)** to bypass AlphaFold lookup and use UniProt sequences even where AlphaFold coordinates exist. Forced mode applies to all mapped accessions by default. To force a subset, include a `Force UniProt accessions` CSV column containing comma- or semicolon-separated mapped accessions for that PDB; a selected accession affects every chain using it. A blank cell forces all accessions. Natural and AlphaFold-required modes ignore that column. Use separate empty folders for each mode, because all previously attempted PDB IDs are skipped. Keep reference structure, distance, seed and other settings identical for paired comparisons, and leave simulation off for the current confidence investigation.

The entry settings record mode, forced accession list, input sources and reasons, stage, app version label and build settings. `Input source` and `Fallback reason` appear on residue rows, prediction rows and chain summaries; `Target accession` and `Target sequence position` apply to either source. Unmatched reference rows retain the intended source when it is known from the input mapping; their predicted position and outcome remain blank. Alignment identity and similarity reflect the modeller's masked-input alignment, not a hidden-reference outcome. Anchor span is the distance between neighbouring aligned anchors in the model; reach capacity is 3.8 Å times the number of backbone steps, and reach ratio is their ratio. Adjacent Cα distances and clash scores describe the generated model at the recorded feature stage. No-anchor cases have no anchor span or reach ratio.

Residue lDDT now includes eligible and compared neighbour counts by neighbour input source, including across chains. An unknown source can reflect an unmatched reference chain. Missing predicted neighbours are still excluded from lDDT and counted separately. Predictions without a reference match remain in `prediction-residues.csv`; missing or mismatched reference residues remain in `residues.csv`. Failure records include a reason code and missing chain list when known; natural AlphaFold absence, lookup failure and invalid chain mapping must not be conflated. Sequence-only models have no AlphaFold pLDDT or PAE, and the existing AlphaFold-derived confidence estimates are unavailable. Forced accessions are never sent to the AlphaFold prediction or PAE endpoints by the input/validation loaders. Feature values after simulation are not part of the no-simulation study.
